Who owns which mapping?

01 / Firecracker userspace

Set up guest RAM

Firecracker maps memory into its host process with mmap, then registers RAM ranges with KVM using memory slots: guest physical ranges paired with host virtual addresses (HVAs). File-backed snapshot restore uses MAP_PRIVATE. [1, 2]

02 / Guest Linux + KVM

Maintain the tables

Guest Linux maintains guest page tables: GVA → GPA. KVM maintains NPT: GPA → HPA, consistent with the host Linux backing pages. An HVA helps KVM find backing; it is not a third hardware stage on every guest access. [2]

03 / CPU hardware

Execute the access

The CPU translates addresses and checks permissions. A usable TLB entry caches the combined GVA → HPA translation in the relevant address-space context. A miss can trigger hardware walks without a VM exit.

“VM exit” means control leaves guest execution for host KVM. It does not necessarily mean KVM_RUN returns to the Firecracker userspace loop. Ordinary RAM backing faults can be handled entirely in the host kernel. Faults are synchronous exceptions tied to an instruction, unlike an asynchronous device interrupt.

CoW, without the shortcut

MAP_PRIVATE is a host mapping policy

The host VMA can allow writes while Linux initially shares clean file-backed pages. Private modifications become anonymous backing; the snapshot file is not written by those modifications. VMs mapping the same file offsets can share resident page-cache pages. MAP_PRIVATE does not eagerly copy all RAM, guarantee all pages remain shared, or perform content-based deduplication. Keep the snapshot file immutable. [1]

There may be no “read-only NPT first” phase

KVM can ask Linux for writable backing while resolving an initial NPT fault, breaking CoW before installing a writable NPT entry—even if the original guest access was a read. The write fault animation assumes the page is still shared and exposed read-only in NPT. Alternatively, a first write to an absent NPT entry can resolve backing, CoW, and NPT installation together. Count transitions in a specific setup, not one universal fault per first guest write.

A 4 KiB copy is our example, not every allocation

This lesson uses a shared, resident, ordinary 4 KiB file-backed page. Linux allocates a private page and copies 4,096 bytes before retrying the write. Huge pages, already-private backing, zero pages, eager prefaulting, dirty logging, and later remapping can change the work and fault count. A permission fault alone does not prove CoW occurred.

What the arrows compress

Hardware walks are interleaved

The GVA → GPA → HPA drawing is a logical model. Guest page-table entries themselves live in guest physical memory, so fetching each entry can require NPT translation too. The walker traverses multiple table levels, with caches reducing work. A TLB miss is not just two RAM reads. NPT faults can happen while accessing page-table pages as well as the final data page.

Missing mapping ≠ allocate a new data page

If a valid RAM memory slot exists but an NPT entry is absent, KVM may only need to install a translation to an existing resident page. Linux may instead fault in file data, allocate anonymous backing, or wait for I/O. An unregistered GPA or device region is a different path, potentially MMIO or an error—not automatically demand-allocated RAM.

Keep this at interview depth

Know who owns each mapping, who executes translation, how exits differ from userspace returns, and how snapshot sharing trades memory for fault/copy latency. For inference and RL infrastructure, connect this to cold starts, working-set size, tail latency, and memory density. You do not need to memorize every page-table bit.

Check your intuition

VM B has completed CoW for this page and now has a stable writable mapping. It writes to that page another 1,000 times. How many additional CoW copies?

Interview takeaway

“The CPU performs two-stage translation, and the TLB can cache the combined result. A TLB miss alone does not exit the VM. A nested mapping fault exits to KVM, which resolves host backing and updates NPT. Snapshot CoW is enforced through Linux private mappings and KVM’s translations; after private writable backing is established, repeated writes do not inherently need more CoW faults.”
